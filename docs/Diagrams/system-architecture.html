Cinema · full stack

System architecture

Ten services, each owning its own database, composed into one schema by a federated gateway. Three of ten subgraphs are drawn; the rest follow the same shape.

Edge

One gateway, three routes

  • /graphql → Fusion gateway
  • /webhooks/psp → payments
  • /redemptions → ticketing
  • No AWS API Gateway, YARP or Ocelot

Data

No shared database

  • One Aurora cluster per service
  • Cross-service data duplicated by event
  • Seat uniqueness is a partial unique index

Realtime

One live surface

  • Seat map only
  • Subgraph SSE passthrough
  • No message broker
